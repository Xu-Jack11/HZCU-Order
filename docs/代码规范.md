# 项目代码规范 (Coding Standards)

**项目名称**: HZCU-Order  
**更新日期**: 2026年1月6日  

---

## 1. 后端规范 (Java / Spring Boot)

### 1.1 命名与基础
- **类名**: 使用 `UpperCamelCase`（如 `OrderService`, `PaymentController`）。
- **方法/变量名**: 使用 `lowerCamelCase`（如 `calculateTotal`, `orderId`）。
- **常量**: 全部大写，单词间用下划线分隔（如 `MAX_RECHARGE_AMOUNT`）。

### 1.2 架构分层规范
- **Controller 层**: 仅处理请求分发、参数校验和统一结果封装。禁止在 Controller 中写业务逻辑。
- **Service 层**: 核心业务逻辑承载地。需定义接口（Interface）与实现类（Impl），保证解耦。
- **Repository 层**: 基于 Spring Data JPA，严禁直接拼接 SQL 字符串。
- **DTO 层**: 数据传输对象，严禁直接将 JPA Entity 暴露给前端。

### 1.3 异常处理与日志
- 使用 `@RestControllerAdvice` 结合自定义异常类实现全局异常拦截。
- 日志级别：开发环境使用 `DEBUG`，生产环境使用 `INFO` 以上。重要业务流转必须记录日志。

---

## 2. 前端规范 (TypeScript / Next.js / 微信小程序)

### 2.1 语言与类型
- 强制使用 **TypeScript**。严禁大量使用 `any`，必须为接口返回数据定义 `Interface`。
- 枚举类型（如订单状态）必须定义为 `enum` 或 `Union Types`。

### 2.2 小程序特有规范
- **单位**: CSS/WXSS 统一使用 `rpx` 进行响应式布局。
- **资源**: 禁止在代码中直接嵌入超过 10KB 的 Base64 图片，统一放入 `images/` 目录。
- **API**: 统一封装在 `utils/request.ts`，页面调用必须通过 `utils/api.ts` 的包装函数。

### 2.3 Web 商家端规范
- 样式隔离：使用 **CSS Modules**（`<filename>.module.css`）。
- 目录结构：App Router 模式下，页面逻辑放置在 `app/`，通用组件放置在 `components/`。

---

## 3. 数据库规范 (MySQL)

- **命名**: 表名和字段名使用小写字母及下划线（如 `user_balance`, `order_status`）。
- **主键**: 统一使用 `BIGINT UNSIGNED` 自增主键，字段名为 `id` 或 `<table_name>_id`。
- **通用字段**: 所有表必须包含 `created_at` (DATETIME) 和 `updated_at` (DATETIME) 字段。
- **索引**: 针对查询频繁的 `user_id`, `order_no`, `status` 等字段建立必要索引。
