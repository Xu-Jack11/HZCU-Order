# 小组代码规范（HZCU-Order）

> 统一团队编码方式，减少沟通成本，提高可维护性。

## 通用原则
- 代码优先可读性：明确命名、短小函数、避免过度魔法。
- 单一职责：模块/类/函数职责清晰。
- 最小变更：修复问题时尽量局部、避免牵连无关文件。
- 约定先行：接口、字段、状态枚举统一在文档和类型中定义。

## 目录与命名
- 目录结构保持现状：`backend/`、`web/`、`wxapp/`、`docs/`。
- 文件命名：
  - Java 类用大驼峰：`CanteenService.java`、`ShopJdbcRepository.java`。
  - TypeScript/React 组件大驼峰：`OrderCard.tsx`，样式与组件同名：`OrderCard.module.css`。
  - 脚本与工具小写中划线：`export-diancan.js`。
- 数据库表：统一小写下划线或清晰复数；本项目约定：`canteenshops`（已从 `shops` 迁移）。

## 后端（Java/Spring Boot）
- 包结构：`com.hzcu.order.{controller|service|repository|data|model}`。
- 控制器：
  - 使用 RESTful 路由；返回统一响应结构（分页：`{ list, total }`）。
  - 路由前缀：`/api/v1`。
- 服务层：
  - 业务逻辑不直接访问数据库；依赖 `repository` 层。
  - 避免在服务层做过多 DTO 映射，使用专用 mapper 或轻量方法。
- 仓储层：
  - SQL 语句集中在 Repository；表名与字段与数据库保持一致。
  - 当前规范：所有商家相关 SQL 均使用 `canteenshops` 表。
- 异常与日志：
  - 捕获异常时补充关键信息（请求参数、资源 ID）。
  - 使用合适的日志级别：`info` 业务流、`warn` 异常分支、`error` 不可恢复。
- 配置：
  - 数据源放 `application.yml`，禁用在代码里硬编码连接字符串。
  - 连接池（Hikari）参数谨慎调整，避免过度占用资源。

## 前端（Web/Next.js/TypeScript）
- 组件：
  - 无状态组件优先；包含状态的组件保持最小状态域。
  - UI 样式用 module.css，类名语义化。
- API 封装：
  - 所有网络请求集中在 `web/lib/api.ts`；统一错误处理与重试策略。
  - 后端路由变更时，仅需在此处调整。
- 类型与接口：
  - 使用 TypeScript 类型定义所有接口返回与参数结构。
  - 避免 `any`；必要时用 `unknown` + 运行时断言。
- 测试：
  - 单测使用 Jest；组件测试覆盖关键交互。
  - API mock 与真实调用分层，避免耦合。

## 微信小程序
- 页面与组件拆分：页面（`pages/*`）与工具库（`utils/*`）职责清晰。
- 资源：图片路径与命名统一在 `images/` 下，子目录按业务分类（`shops/` 等）。
- 接口调用：统一使用 `utils/api.ts`，避免分散的 `wx.request`。

## 数据库规范
- 表命名：业务含义清晰，统一风格；本项目采用 `canteenshops` 存储商家数据。
- 字段：
  - 必填用 `NOT NULL`，默认值明确；
  - 数值类型匹配实际范围（如 `BIGINT` 主键，`INT` 计数，`DECIMAL(10,2)` 金额）。
- 约束：
  - 主键、唯一索引、外键明确；
  - 变更表名需评估依赖（触发器、视图、外键、应用代码）。
- 迁移：
  - 提供独立 SQL 脚本（如 `docs/rename_shops_to_canteenshops.sql`）；
  - 变更后同步更新仓储层 SQL 与导出工具。

## 提交与分支
- 分支策略：`main` 稳定；`feat/*` 新功能；`fix/*` 修复；`chore/*` 杂项。
- 提交信息：
  - 格式：`type(scope): summary`（如 `feat(backend): switch shops to canteenshops`）。
  - 描述包含动机与影响（接口/表/配置变更）。
- 代码评审：
  - 每个 PR 至少一名同伴审阅；
  - 大改动需列出影响面与回滚方案。

## 文档与可维护性
- 任何对外接口或表结构变更需更新 `docs/PROGRAM_INVENTORY.md` 与相关 API/DB 文档。
- 新增工具/脚本需在 `tools/README.md` 增加使用说明。

## 质量保障
- 构建：后端 `mvn clean package`，前端 `npm run build`；在 CI 中执行。
- 测试：关键路径必须有单测；后端可引入集成测试验证数据库交互。
- 格式化：
  - 前端使用 ESLint + Prettier（已存在 `eslint.config.mjs`、`tsconfig.json`）。
  - 后端使用 IDE 格式化（统一缩进与换行），避免提交混乱的格式。

## 安全与合规
- 连接凭据使用本地开发配置，不提交生产密钥。
- 禁止引入未知来源的第三方库；如需，引入前评估许可证与安全性。

## 变更清单示例（表名迁移）
- SQL：执行 `ALTER TABLE shops RENAME TO canteenshops;`
- 代码：`ShopJdbcRepository` 中所有 `FROM shops` 改为 `FROM canteenshops`；插入语句同理。
- 导出工具：`tools/export-diancan.js` 已在输出层将 `shops` 映射为 `canteenshops`。
- 文档：更新 PROGRAM_INVENTORY 与 DB 文档，标注迁移。
