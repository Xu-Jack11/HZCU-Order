# 个人项目总结 - 赵晓凯

## 1. 清晰定位：项目概述与个人角色
**项目背景**：
城院点餐项目是为浙大城市学院（HZCU）量身定制的校园订餐系统。该项目旨在解决校园食堂在高峰时段的拥挤排队问题，通过数字化手段连接学生（用户端）、食堂档口（商家端）与学校后勤（管理员端），实现高效的点餐、接单及财务管理。

**个人角色**：
在本项目中，我担任**系统分析师与设计负责人**。主要负责从业务需求到技术方案的转化，确保系统逻辑的严密性与用户体验的合理性，并深度参与了项目交付文档与演示材料的编写工作。

---

## 2. 量化成果：具体工作与核心产出
在项目周期内，我高质量完成了以下核心交付物：
- **核心设计文档**：
    - 独立编写了完整的《需求说明书 (SRS)》。
    - 参与撰写《可行性分析报告》，负责技术可行性部分。
    - 完成了《概要设计说明书》，确立了系统的模块划分与技术选型。
- **逻辑与流程建模**：
    - 针对商家端编写了详细的**伪代码**，并绘制了配套的 **Jackson 图**与多级**数据流图 (DFD)**。
    - 绘制了涵盖用户端、商家端、管理员端的全链路**业务流图**。
- **交互与用户体验**：
    - 完成了全套**界面原型设计**，为前端开发提供了直观参考。
    - 参与编写了《用户手册》，确保最终用户能快速上手系统。
- **项目辅助与演示**：
    - 参与了《实现和测试》及《维护》阶段翻转 PPT 的部分编写。
    - 负责了 30% 的**会议纪要**整理，记录了关键决策过程。

- **多维视角切换**：在设计业务流图和编写用户手册时，能够频繁切换学生、商家和管理员三种视角，确保设计的全面性。

## 6. 坦诚复盘：问题反思与改进方案
**存在问题**：
- **初期逻辑覆盖不全**：在最初设计商家端流程时，对异常退款等边缘情况考虑不够周全。
- **文档迭代压力**：在项目后期，由于同时参与 PPT 和用户手册编写，时间管理上曾出现短暂的紧迫感。

**改进方案**：
- **深度建模校验**：后续通过 Jackson 图对复杂逻辑进行二次校验，成功补齐了逻辑短板。
- **优化时间分配**：在未来的项目中，将更早地启动辅助性文档（如用户手册）的框架搭建，分散后期压力。

## 7. 展望未来：经验总结与成长规划
**经验总结**：
本项目让我完成了从“写代码”到“设计系统”的思维转变。我认识到，优秀的系统设计是成功开发的一半，而完善的辅助文档（用户手册、PPT）则是项目专业性的体现。

**成长规划**：
- **深度学习架构**：未来计划深入学习微服务架构设计，探索如何在高并发校园场景下优化系统性能。
- **全栈能力提升**：在保持设计优势的同时，加强对前端框架和后端中间件的实战应用。
- **持续优化交付物**：探索更高效的自动化文档与演示工具，提升设计交付的质量与效率。
