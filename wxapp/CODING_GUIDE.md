## 基础原则
- 优先使用 TypeScript，启用严格类型，避免 `any`；无法避免时补充简短注释说明原因。
- 组件/页面保持单一职责：数据获取、展示、事件处理分开组织。
- 杜绝魔法值：常量集中在顶部或单独文件。
- 保持无障碍与交互可达：按钮必须可点击且有反馈；loading/错误态需提示。

## 项目结构
- 页面：`miniprogram/pages/<name>/`，仅放与该页面直接相关的逻辑与样式。
- 工具：`miniprogram/utils/`，按领域拆分：
  - `api.ts`：API 封装（对齐 `docs/API/API.md`，统一出口）。
  - `request.ts`：请求封装（基地址、超时、鉴权头）。
  - `mock.ts` / `data.ts`：演示数据。
  - `cart.ts` / `favorite.ts` / `coupon.ts`：本地存储与状态工具。
- 资源：`miniprogram/images/`，禁止在代码里写 Base64。

## 编码规范
- 命名：驼峰；布尔用 `is/has/can/should`；事件处理用 `onXxx`/`handleXxx`。
- 页面数据：`data` 里只存 UI 绑定字段；无需绑定的临时数据放实例属性。
- 异步：统一使用 `async/await`，接口调用捕获错误并提示 `wx.showToast`。
- 判空：使用显式判断；避免链式可能的 undefined 运行时错误。
- 日志：仅在调试阶段使用 `console`，提交前移除或加 TODO。
- 注释：保持简短，解释「为何」而非「做什么」。

## 接口与数据
- 所有接口调用走 `utils/api.ts`，严禁在页面里直接写 URL。
- 新增接口时：
  1) 在 `api.ts` 按模块增加函数，默认遵循 `docs/API/API.md` 路径与 method。
  2) `USE_MOCK` 默认 `true`，保留演示；接入真实后端时改为 `false` 并在 `request.ts` 设置 `BASE_URL`、鉴权。
  3) 需要结构化响应时使用 `unwrap` 统一从 `{ code, data }` 取值。
- 数据模型：优先定义接口类型，避免 `any`；复用已有 `ShopItem`/`GoodsItem` 等。

## 样式规范
- 单位：小程序样式统一使用 `rpx`；颜色/间距抽取为变量时以 `--primary-color` 等命名。
- 布局：使用 flex 代替绝对定位；避免固定高度导致溢出。
- 主题：遵循 README 中的主色（#007AFF）与辅助色；保持留白与阴影一致。
- 交互态：按钮/卡片添加 `:active` 或 class 切换，提供按压反馈。

## 状态与存储
- 本地持久化统一使用工具：购物车 `cart.ts`，收藏 `favorite.ts`，优惠券 `coupon.ts`。
- 存储 key 需常量化，避免重复定义。
- 清理策略：下单/取消时同步清理对应缓存，防止脏数据。

## 交互与可用性
- Loading/空态：接口请求时加 `loading` 标记并在页面展示；无数据时给出空态和行动按钮。
- 错误提示：`showToast` 或 `showModal` 给出可理解文案；失败后应允许重试。
- 表单校验：必要字段前置校验，阻止提交并提示原因。
- 无效入口：禁止跳转到不存在的页面，需用弹窗或灰化说明。

## 提交流程
- 新增/修改页面需自测基本流程（加载、交互、提交）。
- 提交前检查：
  - 是否删除了临时日志/调试代码。
  - 是否保持 `USE_MOCK` 的默认行为与说明一致。
  - 是否更新相关文档或 README 中的能力描述。
